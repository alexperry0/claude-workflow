Building /session-slides

A multi-agent learning-deck skill — designed, built, and dogfooded in a single session.

2026-06-16 · Claude Opus 4.8 · generated by /session-slides

The problem

Why this existsCapturing what a session taught you

  • Goal: turn a finished Claude Code session — the brainstorm → plan → ultra-code loop — into a slide deck you can reopen later.
  • It's a personal memory aid, not a deliverable for others.
  • The primary input is the conversation transcript (the "experience"), not just the code diff.
  • Framed as open-ended research: output format, workflow shape, and where decks live all had to be decided during the session.

The approach

DecisionsThree forks, resolved up front

  • Self-contained HTML over reveal.js/CDN or Figma Slides — chosen for offline durability and archivability.
  • Full 4-phase multi-agent over a single pass — to actually exercise Opus 4.8 multi-agent patterns.
  • Decks committed to docs/session-decks/ over a gitignored folder — versioned, shareable, persistent.
  • Packaged to repo convention: a command + a reusable harvester agent + a template (orchestration / harvest / presentation split).

Key insightDesign to the model's grain

  • Opus 4.8 under-delegates → the skill mandates an explicit 5-way parallel fan-out, "do not collapse it into one pass."
  • Opus 4.8 over-narrates & over-asks → subagents return structured digests and are told to work autonomously.
  • Fresh-context verifiers beat self-critique → Phase 4 is a zero-context reviewer, mirroring the repo's "Fresh Eyes Review."
  • Accuracy over polish: every slide bullet must trace to a harvester's evidence — a fabricated lesson is worse than a missing one.

The experience

For frontier-model tooling, the best available model can vanish mid-design.

— Fable 5 was disabled 3 days after launch, mid-session

Pitfalls & surprisesWhat tripped us up

  • Fable 5 / Mythos 5 disabled (2026-06-12, export-control directive) — the assumed model was gone; default fell back to Opus 4.8.
  • In this repo, "skills" are .claude/commands/*.md slash commands — not the Anthropic SKILL.md format.
  • Effort can't be read or set in-session — it's a harness/API request parameter, not something the agent controls.
  • Live-test gotcha: the brand-new harvester agent wasn't registered mid-session (agents load at startup) — the run fell back to general-purpose subagents.

The outcome

Shipped & verifiedFour files, dogfooded on itself

  • Created the command, the learning-harvester agent, the learning-deck.html template, and the output-dir README.
  • The skill auto-registered and was run end-to-end on the very session that created it.
  • Verification is fresh-eyes by design, not automated tests (this repo has no test framework — validation is by running against inputs).
  • Nothing committed yet — work sits on a feature branch; commits go through the branch/PR flow on request, never to main.

RecapWhat I'd carry forward

  • Shape multi-agent workflows to the model's actual behavior — for Opus 4.8, that means explicit delegation, structured handoffs, and a fresh-eyes verifier.
  • Pin model defaults to real-world facts with a reversible note, so tooling survives sudden availability changes.
  • Newly authored agents need a fresh session to register — expect a fallback when dogfooding immediately.
  • For artifacts meant to last, self-contained & offline beats anything that depends on a CDN or a hosted tool.
  • Dogfooding a tool on its own creating-session surfaces the real gotchas fastest.
